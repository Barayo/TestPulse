## Why

As an anonymous visitor browsing a public project, when I land on `/public/{key}`, I want to see exactly the same dashboard, Library, Suites, and Runs pages a logged-in member sees — because right now I don't: `/public/{key}` is a separate, hand-maintained, deliberately minimal page (`PublicProjectPage.tsx`), and it has already visibly drifted from the real project pages twice in one week (missing classification pills, missing the summary-strip dashboard layout entirely). The parallel-implementation approach `enable-public-project-access` chose was a reasonable bet at the time — smaller blast radius, no auth-architecture risk — but its own design.md flagged the exact failure mode that has now happened twice: *"Reusing authenticated page components for the anonymous view... could regress if a future page adds a control that doesn't check `MyPermissions` correctly."* Maintaining a second frontend by hand doesn't scale as the authenticated UI keeps evolving; every future page change now needs a matching public-page change that's easy to forget.

## What Changes

- **One set of pages, one set of URLs, for every visitor.** `ProjectPage`, `FolderExplorerPage`, `CaseDetailPage`, `SuitesPage`, `SuiteDetailPage`, `RunsPage`, `RunPage`, and `RunItemDetailPage` become dual-mode: authenticated members with access see the full read/write experience exactly as today; anonymous visitors on a project that is publicly accessible (per the existing two-flag `publicAccess` + `publicProjectsEnabled` check) see the identical page, sourced from the existing `/api/v1/public/*` read API, with every write control hidden.
- **Prerequisite: uniform write-control permission-gating.** `SuitesPage`, `RunPage`, `CaseDetailPage`, `RunItemDetailPage`, `NewRunPage`, and `SuiteDetailPage` currently render write controls unconditionally for any authenticated user (relying on the server's `403`) — a pre-existing inconsistency (backlog issue #110) that this change turns into a hard prerequisite, since anonymous visitors can no longer rely on "you'll never even see this page" to make an ungated button safe.
- **`RequireAuth` stops hard-gating project-content pages.** It continues to hard-gate every account-only page (Project Settings, Project Members, People, Roles, Tokens, Instance Settings, Profile) exactly as today — none of those gain a public equivalent. The eight project-content pages above resolve their own data (authenticated call if a session exists, public call otherwise) and fall back to the existing "not found" messaging, now also covering "this exists but isn't public and you're not signed in."
- **The project list (`/`) becomes the discovery surface for anonymous visitors.** Authenticated behavior is unchanged (a member's own projects, or straight to their one project). An anonymous visitor sees every publicly accessible project on the instance — zero, one (auto-continue to it), or many (a list) — replacing the standalone discovery index built for this in `add-public-project-discovery`.
- **BREAKING (internal, not to any external contract):** `/public/{projectKey}` and `/public` are retired as distinct pages and become redirects to `/projects/{projectKey}` and `/`, so any already-shared or documented link keeps working. `PublicProjectPage.tsx`, `PublicProjectsIndexPage.tsx`, `usePublicProjects.ts`, and the discovery-specific parts of `PublicHeader.tsx` are deleted; the anonymous-viewer banner they introduced is kept, moved into the shared `Layout`.
- **No backend route or auth-model change.** `mountPublicAPI`'s separate, hand-picked-whitelist route tree (`/api/v1/public/*`) stays exactly as it is and becomes the frontend's anonymous data source for the unified pages. `authenticate`, `requirePermission`, and every authenticated route are untouched, matching the explicit non-goal `enable-public-project-access/design.md` already established (that blast-radius argument still holds and isn't being revisited).
- **One deliberate, permanent gap, not a bug to fix later:** `CaseDetailPage`/`RunItemDetailPage`'s version/result-history author names come from `GET /api/v1/users` (authenticated-only, unscoped — returns every user's email and admin status). It gets no public equivalent; the anonymous view omits the author name rather than closing this one remaining visual gap (design.md D10, added after a 2026-08-10 security review flagged the risk of a future contributor "fixing" this by exposing user identity anonymously).
- **Route categorization becomes structural, not just documented.** `App.tsx` gains two explicitly named route groups (`ACCOUNT_ONLY_ROUTES`/`PROJECT_CONTENT_ROUTES`) plus a test asserting every route is categorized, so a future page can't silently skip authorization review by omission (design.md D9, same security review).

## Capabilities

### New Capabilities
(none)

### Modified Capabilities
- `public-project-access` (capability introduced by `enable-public-project-access`, extended by `add-public-project-discovery`; neither has been archived, so no main spec exists yet — this change's delta spec is written against the same not-yet-archived capability, continuing the reconciliation note both prior changes already flagged): retires the standalone `/public` discovery index requirement in favor of the project list itself resolving zero/one/many for anonymous visitors, and adds the core new contract — every project-content page renders identically for authenticated and anonymous visitors, sourced from the unchanged public read API. `ui-navigation`'s existing "Project list..." requirement is unaffected — it describes authenticated-path behavior only; the anonymous case is specified here instead, the same choice `add-public-project-discovery` already made for the discovery index.

## Impact

- **Backend**: none. `mountPublicAPI` and its existing read routes are reused as-is.
- **Frontend**: `App.tsx` (route table restructured into `ACCOUNT_ONLY_ROUTES`/`PROJECT_CONTENT_ROUTES` with a manifest test; `/public/*` become existence-blind redirects), `ProjectPage.tsx`, `FolderExplorerPage.tsx`, `CaseDetailPage.tsx`, `SuitesPage.tsx`, `SuiteDetailPage.tsx`, `RunsPage.tsx`, `RunPage.tsx`, `RunItemDetailPage.tsx`, `NewRunPage.tsx`, `SuiteActionsMenu.tsx` (permission-gating retrofit — broader than first assessed, see design.md D4), `ProjectsPage.tsx` (anonymous discovery behavior), `Layout` (anonymous banner + Log in affordance). Deletions: `PublicProjectPage.tsx`, `PublicProjectsIndexPage.tsx`, `usePublicProjects.ts`, `PublicHeader.tsx` and their tests.
- **E2E**: `public-project-access.spec.ts` rewritten against the unified URLs; new coverage for the write-control-gating retrofit and the auth-resolution loading-race fix (design.md D2).
- **Docs**: `docs/test-management.md`'s "Public project access" section, `docs/getting-started.md`.
