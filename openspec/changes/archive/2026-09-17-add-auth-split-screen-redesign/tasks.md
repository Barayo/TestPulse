## 10. Bugs found during founder review, fixed within this change

Two real defects were found by the founder reviewing the live deployed pages (not caught by any automated test or by the initial browser verification in 9.5) and fixed as part of this change, since both are specific to the auth screen family this change owns.

- [x] 10.1 **Unstyled browser autofill.** Chrome's native `:-webkit-autofill` fill (triggered by a real saved credential) rendered as an unthemed blue box clashing against the new dark brand pane — the global `Input` component (`apps/web/src/components/ui/input.tsx`) had no `:autofill`/`:-webkit-autofill` handling in either theme, a pre-existing gap made newly visible by this change's dark branded background. Fixed in `apps/web/src/index.css`'s `@layer base` block with the standard inset-`box-shadow` + `-webkit-text-fill-color` override (the only way to beat the browser's internal UA style, since `background-color` can't win against it), using `var(--card)`/`var(--foreground)` tokens so it follows both themes. No automated regression test: `:-webkit-autofill` is a real-browser-only pseudo-class jsdom/vitest cannot render or trigger — verified instead by real Chrome autofill in a live deploy (founder-confirmed).
- [x] 10.2 **Dark theme collapsed the two-pane split.** When the visitor's own theme was Dark, `AuthLayout`'s brand pane (forced dark via a nested `.dark` class per D4) used `bg-background`, the same token the now-actually-dark page canvas also renders — so the brand pane and the page behind the form pane became literally the same color, and the `Card`'s existing `ring-1 ring-foreground/10` elevation cue was too subtle against this palette's close dark values to read as a floating surface. The entire "two distinct panels" concept Direction B depends on silently disappeared in Dark theme (Light theme was unaffected — its background/card/forced-dark values are genuinely far apart). Fixed by Pepe (dispatched for this specific regression) in `apps/web/src/components/AuthLayout.tsx` (brand pane fill switched to `bg-sidebar`/`text-sidebar-foreground` — a token genuinely distinct from `--background` in every palette, and semantically correct: this pane is a persistent structural side panel, the same role `--sidebar` already plays for `AdminShell`'s nav) and `apps/web/src/index.css` (a `.auth-form-pane [data-slot='card']` rule scoped to just this subtree adding a real drop shadow + light rim, rather than changing `Card` everywhere it's used). Verified live in both themes after rebuild: Dark now shows a clearly lighter brand pane against a visibly darker page canvas and a login card with an unambiguous cast shadow; Light is visually unchanged in composition (plus gained the same subtle shadow). `npx vitest run` (full suite, 1764 tests), `npx tsc -b`, and `make lint` all confirmed clean after the fix — no test asserted the specific class names that changed.
